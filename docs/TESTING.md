# Testing

| Area                    | Where                      | What                                                                                                                                                                                                                                                                       |
| ----------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Learning engine         | `learning-engine`          | mastery rise/decay/staleness, repeated & overconfident mistakes, hints, FSRS scheduling/lapses/retrievability, difficulty/frustration, weak-prerequisite detection, XP/levels/streaks                                                                                      |
| Recommendation          | `recommendation-engine`    | affinity learning & shrinkage, Model A vs B separation, scoring invariants (explainability sums), difficulty fit, review exemption, exam pressure, eligibility reasons, determinism, diversity/exploration, low inventory, closed-loop behaviour change, Thompson sampling |
| Validation              | `validation`               | all question-type schemas, grading incl. partial credit, answer-leak stripping, notes/maps/envelope                                                                                                                                                                        |
| Content engine          | `content-engine`           | license decisions, dedup, quality gates, batch/rate guard, job state machine, backoff, secret sanitising                                                                                                                                                                   |
| Analytics / shared / AI | respective packages        | taxonomy hygiene, sanitiser, redaction, model gating, truthful unavailability, cancellation                                                                                                                                                                                |
| **DB: migrations**      | `database/test/migrations` | apply cleanly; **RLS on every table**                                                                                                                                                                                                                                      |
| **DB: security**        | `database/test/security`   | ~40 attack/permission scenarios (see AUTHORIZATION.md)                                                                                                                                                                                                                     |
| **DB: parity**          | `database/test/parity`     | SQL enums/rate limits/gates/flags ↔ TypeScript                                                                                                                                                                                                                             |

| Mobile logic            | `apps/mobile`              | event queue (cap/backoff), feed windowing, uuid                                                                                                                                                                                                                            |
| Builds (CI)             | `.github/workflows/ci.yml` | `next build` (admin), `expo export` (Metro bundle)                                                                                                                                                                                                                         |

Harness: `packages/database/test/harness.ts` — PGlite + Supabase stub (roles anon/authenticated/service_role, `auth.users`, `auth.uid()`, minimal `storage`), `Actor` helper (`q`, `fails`, `denied`) to run SQL _as a user_.
Limits: not real Supabase (GoTrue/Realtime/Storage service/Edge Runtime untested). **Gaps / TODO:** Supabase-local integration job; Edge Function tests (Deno); mobile component tests (jest-expo/RNTL); Detox/Maestro E2E for sign-up→feed→answer→save; performance tests (feed latency at scale, query plans, memory on low-end Android); accessibility audits.
Principles: test behaviour that matters (security, learning integrity, ranking invariants), not coverage percentage.
